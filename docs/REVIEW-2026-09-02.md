## Decisions taken on 2026-09-02

Recorded here because DECISIONS.md was excluded from this pass. Each needs an
amendment entry there.

- Q-009: recovery points use Snapper pre and post pairs instead of a custom
  Btrfs snapshot manager. Requirements unchanged. Rejected alternative: direct
  `btrfs subvolume` management, because Snapper already owns that lifecycle on
  Fedora and principle 3 forbids weak replacements.
- Q-010: the Windows guest runs in the `dockurr/windows` container on Docker
  with KVM, data below `/var/lib/nimbus/windows/` on the `windows` subvolume,
  following Omarchy's `omarchy-windows-vm`. Rejected alternatives: system
  libvirt, kept as the earlier choice; a Docker named volume, rejected because
  the data path would be hidden below `/var/lib/docker`.
- Q-006 and Q-002 were reviewed and kept: COPR RPM delivery with packaging in
  a separate repository, and the selector origin compared against
  `.git/config` without running Git. Rejected alternative for Q-006: building
  the engine from the definitions checkout, because the mutable checkout must
  not execute code.
- Handoff: `managed_by_nimbus` joins `machine` and `profiles`; `windows-vm`
  joins the profile vocabulary, named to avoid the dotfiles `windows` platform
  profile.
- D-007 is resolved: the dotfiles repository removed its machine manifests and
  symlink selector and adopted the handoff.
